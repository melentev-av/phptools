# Phan Integration for OpenIDE

Проблемы [Phan](https://github.com/phan/phan) прямо в редакторе OpenIDE, quick-fix `@phan-suppress-next-line` и панель с отчётом.

> Плагин для OpenIDE. Работа в IDE JetBrains не поддерживается и не тестируется.

## Требования

- Phan в проекте (`composer require --dev phan/phan`) либо путь к бинарнику в настройках.
- Конфигурация `.phan/config.php` (создать: `vendor/bin/phan --init --init-level=3`).
- **Расширение `php-ast`** — желательно. Без него плагин запускает Phan с `--allow-polyfill-parser` (включено по умолчанию): работает, но заметно медленнее. Установка: `pecl install ast` и `extension=ast.so` в `php.ini`.

## Почему по умолчанию «При сохранении»

Phan анализирует всю программу: даже для одного файла он разбирает все папки из `directory_list`. В небольшом Laravel без `php-ast` это около 10–15 секунд на проверку. Кроме того, Phan CLI не умеет анализировать несохранённый буфер. Поэтому режим по умолчанию — «При сохранении», таймаут — 120 с. Режим «При вводе» для Phan ведёт себя так же, как «При сохранении».

## Как работает

- Проверяется сохранённый файл (`-I <файл>`), в рабочей папке ближайшего владельца `vendor/` — там же `.phan/`.
- Подсказка: текст проблемы, имя проверки ссылкой на документацию Phan и важность (низкая / обычная / критичная). Проблемы низкой важности — слабые предупреждения.
- Quick-fix (Alt+Enter) «Подавить через @phan-suppress-next-line» вставляет `// @phan-suppress-next-line PhanXxx` над строкой или дописывает проверку через запятую в такой же комментарий.
- Файлы вне `directory_list` пропускаются молча.
- Включается и выключается инспекцией **Phan validation** (Settings → Editor → Inspections → PHP tools); Code → Inspect Code тоже запускает Phan.

## Панель Phan

Иконка Phan в левой полосе: вкладки **Изменённые файлы** (проверка выбранных, всех, текущего файла или всего проекта) и **Отчёт** (дерево «файл → проблемы», ссылки на документацию, переход к коду, подавление проблемы, фильтр, группировка по проверке, экспорт в Markdown). В дереве Project — «Проверить Phan» для файлов и папок (папки раскрываются в PHP-файлы).

## Настройки

Settings → Tools → Phan. Хранятся в `.idea/phan-tools.xml` — файл можно коммитить.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| Когда проверять | При сохранении | «При вводе» = «При сохранении» для Phan; «Только вручную» — Inspect Code и панель |
| Бинарник | пусто | Пусто — `vendor/bin/phan` рядом с файлом и выше до корня проекта |
| Файл конфигурации | пусто | `-k`; пусто — `.phan/config.php` |
| PHP-интерпретатор | пусто | Запуск как `<php> <phan>` |
| Доп. аргументы | пусто | Добавляются в командную строку |
| Таймаут | 120 с | Один запуск |
| Polyfill-парсер | вкл. | `--allow-polyfill-parser` |
| Лимит памяти | пусто | `--memory-limit` |
| Процессов | 1 | `-j`, только для панели |

## Docker Compose / Laravel Sail

Включите «Запускать в Docker Compose» и укажите сервис (для Sail — `laravel.test`, путь `/var/www/html`). В стандартных PHP-образах `php-ast` обычно нет — polyfill-парсер оставьте включённым или добавьте расширение в образ.

## Планы

Режим демона Phan (`--daemonize-tcp-port` + `phan_client`) — быстрая проверка при вводе и несохранённых файлов. Не в v0.1: нужен управляемый фоновый процесс.
