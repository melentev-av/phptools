# Бриф 01a — Плагин PHPStan: подсветка в редакторе

> Предусловие: выполнен бриф 00 (скелет и `core`). Работать в модуле `phpstan/` и, где сказано, в `core/`.
> Продолжение — бриф **01b** (боковая панель и отчёт).

> **Целевая платформа — только OpenIDE.** Не PhpStorm и не другие IDE JetBrains: сборка, тесты, ручная проверка и публикация (marketplace.openide.ru) только под OpenIDE; никаких зависимостей от PHP-плагина JetBrains (`com.jetbrains.php`). Любое API платформы проверять по jar'ам и исходникам OpenIDE, а не по документации JetBrains, и записывать в `docs/api-notes.md`. Подробно — разделы «Целевая платформа» и «Как проверять API» в брифе 00.

## Цель

Плагин подсвечивает ошибки PHPStan прямо в редакторе OpenIDE — при вводе (в том числе в несохранённом файле), при сохранении или только по команде — и даёт quick-fix «игнорировать ошибку». Работает и локально, и через Docker Compose. Larastan подхватывается автоматически, потому что это просто конфиг PHPStan.

## Метаданные

- Plugin ID: `dev.phptools.phpstan`, имя: **PHPStan Integration** (for OpenIDE).
- `<depends>com.intellij.modules.platform</depends>`.
- Группа уведомлений: `phpstan`.
- Инспекция: shortName `PhpStanInspection`, displayName «PHPStan validation», groupName «PHP tools», `enabledByDefault="true"`, `level="WARNING"`, **без** атрибута `language`. Класс: `LocalInspectionTool(), ExternalAnnotatorBatchInspection`. Описание — `resources/inspectionDescriptions/PhpStanInspection.html`.
- Аннотатор: `<externalAnnotator language="PHP" implementationClass="...PhpStanAnnotator"/>`.
- Настройки: `<projectConfigurable parentId="tools" id="dev.phptools.phpstan" displayName="PHPStan" .../>`.
- Уже сделано в брифе 00: `RehighlightOnSave`, `PhpStanBuiltInCheck` (предложение выключить встроенный анализатор PHP-плагина), `PhpStanTool.SPEC`.

## Режим проверки (изменение в `core`)

Решение: пользователь выбирает, когда запускается проверка в редакторе. Это общая настройка для всех инструментов, поэтому она живёт в `core`.

- `ToolState.checkMode: CheckMode` — `ON_TYPING` (по умолчанию) / `ON_SAVE` / `MANUAL`.
- В `ToolConfigurable` — радиокнопки «Когда проверять»: «При вводе», «При сохранении», «Только вручную (из панели)».
- `ToolExternalAnnotator`:
  - `MANUAL` — `collectInformation` сразу возвращает `null`, процесс не запускается;
  - `ON_SAVE` — несохранённый документ откладывается в `PendingRehighlight` (как при `canAnalyzeUnsaved == false`);
  - `ON_TYPING` — анализ несохранённого буфера, если инструмент это умеет (`canAnalyzeUnsaved`), иначе ведёт себя как `ON_SAVE`.
- Отдельной настройки `editorMode` больше нет: её роль играет `checkMode`.

## Настройки (поверх `ToolState`)

| Поле | Тип | По умолчанию | Аргумент CLI |
|---|---|---|---|
| `memoryLimit` | String | `"1G"` | `--memory-limit=<v>` (пусто — не передавать) |
| `level` | String | `""` | `--level=<v>` — **только если уровня нет в конфиге** (см. ниже) |

`timeoutSeconds` по умолчанию **60**: PHPStan на больших проектах медленный.

### Уровень

Решение: уровень по умолчанию берётся из конфигурации проекта; выбор в настройках доступен, только если в конфиге уровня нет.

- Читать `phpstan.neon` самим ненадёжно (`includes`, конфиги Larastan), поэтому спрашиваем PHPStan: `phpstan dump-parameters --json [-c <config>]` → `parameters.level`. **Перед реализацией проверить**, что команда есть в поддерживаемых версиях и какой у неё формат вывода; записать в `docs/api-notes.md`.
- При открытии страницы настроек запрос выполняется в фоне (без блокировки UI).
  - Уровень в конфиге есть — показать «Уровень: 6 (из phpstan.neon)», выбора нет, `--level` не передаётся.
  - Уровня нет — выпадающий список: пусто, `0`–`10`, `max`. Пусто — `--level` не передаётся, PHPStan решает сам.
  - PHPStan не найден или команда упала — показать выпадающий список и подсказку, что уровень из конфига прочитать не удалось.

## Запуск

```
<phpstan> analyse
    --error-format=json
    --no-progress
    --no-interaction
    [--memory-limit=<memoryLimit>]
    [-c <toTarget(configPath)>]
    [--level=<level>]                                    # только если уровня нет в конфиге
    <extraArgs...>
    [--tmp-file=<tmp> --instead-of=<toTarget(file)>]     # только ON_TYPING и если буфер несохранён
    <toTarget(file)>
```

Рабочая папка — владелец `vendor` (из `core`), поэтому `phpstan.neon` / `phpstan.neon.dist` и Larastan находятся сами.

### Анализ несохранённого буфера

PHPStan умеет анализировать временный файл так, будто это файл проекта: `--tmp-file` и `--instead-of`. По нашим данным это появилось в **PHPStan 2.1.17 и 1.12.27** (сверить с phpstan.org → «Editor mode»).

- `canAnalyzeUnsaved(project) = state.checkMode == ON_TYPING && !unsupported[project]`.
- Буфер несохранён: `tool.runWithTempFile(input.text, "php") { tmp -> args(..., tmp) }`.
- Если в stderr есть `tmp-file` и признак неизвестной опции (`does not exist`): `unsupported[project] = true` (сброс при Apply настроек), файл в `PendingRehighlight`, вернуть `null`. Один раз за сессию — информационное уведомление: «Ваша версия PHPStan не поддерживает анализ без сохранения, проверка будет после сохранения. Обновите PHPStan до 2.1.17+ / 1.12.27+».
- Буфер сохранён — запуск без временного файла.

## Разбор вывода

Коды выхода: **0** — ошибок нет, **1** — найдены ошибки (это нормально); всё остальное — сбой.

JSON в stdout. Перед JSON может оказаться мусор, поэтому парсить с первого `{`:

```json
{
  "totals": { "errors": 0, "file_errors": 2 },
  "files": {
    "/abs/path/src/Foo.php": {
      "errors": 2,
      "messages": [
        { "message": "Call to an undefined method Foo::bar().", "line": 12,
          "ignorable": true, "identifier": "method.notFound", "tip": "..." }
      ]
    }
  },
  "errors": []
}
```

- Ключи в `files` — пути на стороне инструмента (в Docker — пути контейнера). **Не маппить обратно**: анализируется один файл, поэтому берём запись, чей ключ оканчивается на относительный путь файла, а если запись одна — её.
- Непустой верхнеуровневый `errors` (ошибки конфига, autoload и т.п.) — `ToolNotifier.notifyFailure` с текстом ошибок.
- JSON не распарсился или код выхода не 0/1 — тоже `notifyFailure` с хвостом stderr; аннотаций нет.
- **Файл вне анализа** (например, попал в `excludePaths`, и PHPStan сообщает, что файлов для анализа нет) — молча, без аннотаций и без уведомлений. Точный текст/признак проверить на реальном PHPStan и записать в `docs/api-notes.md`.
- Парсер — чистая функция без платформы (Gson из платформы допустим), чтобы её можно было тестировать и переиспользовать в 01b для нескольких файлов.

## Отображение

### Ошибки со строкой

- Сообщение: `PHPStan: <message>`.
- Tooltip (HTML, всё экранировать): сообщение; затем `tip` (если есть) отдельной строкой серым; затем идентификатор `<code>identifier</code>` **ссылкой** на `https://phpstan.org/error-identifiers/<identifier>`. Это обычная ссылка, которую открывает сам пользователь; плагин сетевых запросов не делает.
- Колонок PHPStan не даёт: подсвечивается строка от первого непробельного символа.

### Ошибки уровня файла (`line: null`) — полоса над редактором

Решение: такие ошибки **не** ставятся на строку 1, а показываются полосой над редактором — штатным механизмом платформы (`EditorNotificationProvider`, как «Файл изменён на диске»).

```
┌──────────────────────────────────────────────────────────────┐
│ ⚠ PHPStan: <текст ошибки файла>                       [Скрыть] │
└──────────────────────────────────────────────────────────────┘
```

- Последние ошибки уровня файла хранятся в кэше по файлу (заполняется аннотатором, очищается при следующем успешном прогоне без таких ошибок); после изменения кэша — `EditorNotifications.updateNotifications(file)`.
- Несколько ошибок — первая в полосе, остальные в tooltip или «и ещё N».
- «Скрыть» убирает полосу до следующего прогона.
- В 01b в полосу добавится кнопка «Открыть отчёт».
- API (`EditorNotificationProvider`, `EditorNotificationPanel`, `EditorNotifications`) проверить по jar'ам OpenIDE.

## Quick-fix: `PhpStanIgnoreFix(line, identifier)`

Показывать, только если `ignorable == true` и `identifier != null`.

- Текст: `Ignore '<identifier>' with @phpstan-ignore`, family: `PHPStan: ignore error`.
- Если предыдущая строка, без ведущих пробелов, начинается с `// @phpstan-ignore ` (именно `-ignore `, а не `-ignore-line`/`-ignore-next-line`), дописать `, <identifier>` в её конец.
- Иначе вставить над строкой ошибки новую строку `// @phpstan-ignore <identifier>` с тем же отступом, что у строки ошибки.
- `startInWriteAction() = true`; правка через `Document`, без PSI.
- Логика — чистая функция «текст + номер строки + identifier → новый текст» (её же использует отчёт в 01b).

## Тесты

- Парсер на фикстурах JSON: ошибки есть; ошибок нет; `line: null`; непустой `errors`; мусор перед JSON; пустой stdout; несколько файлов в `files`.
- Сборка аргументов: с конфигом и без; с уровнем и без; уровень из конфига подавляет `--level`; анализ буфера в local (абсолютный tmp-путь) и в docker (`sh -c`-обёртка из `core`).
- Разбор вывода `dump-parameters`: уровень есть, уровня нет, мусор.
- Логика quick-fix: вставка новой строки и дописывание к существующему комментарию.
- `core`: поведение `checkMode` в отборе файлов (чистая логика, если её удастся вынести).

## Ручная проверка (в `playground/`, через `runIdeWithPhp`)

`playground/` — свежий Laravel с `larastan/larastan`, `docker-compose.yml` с PHP-сервисом.

1. `ON_TYPING`: вызов несуществующего метода в контроллере, **не сохранять** — подсветка появляется.
2. Наведение: в tooltip есть `tip` и идентификатор-ссылка на phpstan.org.
3. Quick-fix: появляется `// @phpstan-ignore method.notFound`, после сохранения подсветка уходит.
4. `ON_SAVE`: подсветка появляется только после сохранения. `MANUAL`: PHPStan в редакторе не запускается вовсе.
5. Уровень: в `phpstan.neon` есть `level` — в настройках показан уровень из конфига без выбора; убрать `level` — появляется выпадающий список.
6. Ошибка уровня файла (например, синтаксически сломанный файл или файл, который PHPStan не может загрузить) — полоса над редактором, не волнистая линия на строке 1.
7. Сломать `phpstan.neon` (несуществующий параметр): одно уведомление со stderr и кнопкой «Открыть настройки», не спам на каждое нажатие клавиши.
8. Файл в `excludePaths` — ни подсветки, ни уведомлений.
9. Docker-режим: «Проверить» показывает версию PHPStan из контейнера, подсветка работает.
10. Выключить инспекцию в Settings → Inspections — процесс PHPStan больше не запускается.
11. Code → Inspect Code по папке `app/` — ошибки PHPStan в отчёте инспекций.

## Не делать

- Не анализировать весь проект на каждое изменение: в редакторе — только текущий файл.
- Не писать baseline и не править `phpstan.neon` пользователя.
- Не показывать уведомление, если PHPStan в проекте просто не установлен.
- Не делать сетевых запросов: ссылки на phpstan.org открывает пользователь.
