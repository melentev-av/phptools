# Бриф 01b — Плагин PHPStan: боковая панель и отчёт

> Предусловие: выполнен бриф 01a (подсветка в редакторе, парсер вывода, quick-fix).
> Общие части (панель, отчёт, запуск по нескольким файлам) делаются в `core/`, чтобы их переиспользовали Psalm (02) и PHP-CS-Fixer (03). В `phpstan/` — только подключение.

> **Целевая платформа — только OpenIDE.** Правила те же, что в брифах 00 и 01a: API проверять по jar'ам OpenIDE и записывать в `docs/api-notes.md`, сетевых запросов не делать.

## Цель

Боковая панель PHPStan в той же полосе, где Project, Structure и Commit. Из неё пользователь запускает проверку изменённых файлов (и не только) и читает удобный отчёт со ссылками, переходами к коду и quick-fix. Это основной способ работы в режиме проверки `MANUAL` и дополнение к подсветке в остальных режимах.

## Панель (tool window)

- Регистрация в плагине: `<toolWindow id="PHPStan" anchor="left" icon="..." factoryClass="...PhpStanToolWindowFactory"/>`; фабрика — тонкий наследник общей фабрики из `core`, которой передаётся `ToolSpec` и «анализатор» инструмента.
- Две вкладки: **«Изменённые файлы»** и **«Отчёт»**.
- Панель доступна, только если в проекте есть PHP (или всегда — решить по API `ToolWindowFactory.isApplicable`/`shouldBeAvailable`, проверить по jar'ам).

### Вкладка «Изменённые файлы»

- Список изменённых PHP-файлов из VCS — те же, что во вкладке Commit (`ChangeListManager`), включая новые неотслеживаемые; без `vendor/`, excluded и файлов вне контента проекта. Обновляется при изменениях в VCS.
- Галочки у файлов, по умолчанию отмечены все.
- Кнопки: **«Проверить выбранные»**, **«Проверить все изменённые»**, **«Проверить текущий файл»**.
- Пусто — понятный текст «Изменённых PHP-файлов нет» и кнопка «Проверить текущий файл».

### Запуск из панели и проекта

Решение по умолчанию (уточнить у заказчика, если нужно иначе):

- Изменённые файлы и текущий файл — из панели.
- Файлы и папки — из контекстного меню дерева Project: «Проверить PHPStan».
- Весь проект по `paths` из конфига — отдельная кнопка «Проверить проект» с подтверждением («может занять несколько минут»); запуск `phpstan analyse` без явных путей.

Технически:

- Все выбранные файлы уходят **одним** запуском PHPStan (`analyse ... <file1> <file2> ...`), а не по одному. Если командная строка получается слишком длинной (Windows ~32K символов) — бить на пачки и склеивать результаты.
- Несохранённые документы перед запуском из панели сохраняются (`FileDocumentManager.saveDocuments`), анализ идёт по файлам на диске.
- Фоновая задача с прогрессом и отменой (`Task.Backgroundable`); отмена убивает процесс (как в `core`). Повторный запуск во время работы — отменяет предыдущий.
- Таймаут для пакетного запуска — больше, чем для одного файла (например, `timeoutSeconds × 10`, не меньше 5 минут); уточнить при реализации.
- Ошибки запуска и конфига — как в 01a: `ToolNotifier` с троттлингом, плюс текст ошибки наверху отчёта.

## Вкладка «Отчёт»

Цель — чтобы отчёт было удобно читать и с ним работать.

- **Шапка:** когда запущено, сколько длилось, сколько файлов проверено, сколько ошибок; уровень и конфиг (из `dump-parameters`, см. 01a); локально или Docker.
- **Ошибки запуска/конфига** (верхнеуровневый `errors`) — отдельным блоком над деревом, с полным текстом и кнопкой «Открыть настройки».
- **Дерево:** файл (относительный путь и число ошибок) → ошибки, отсортированные по строке.
  - Строка ошибки: номер строки, сообщение, идентификатор.
  - Под ней серым — `tip`, если есть.
  - Идентификатор — ссылка на `https://phpstan.org/error-identifiers/<identifier>` (открывает пользователь, `BrowserUtil`).
  - Ошибки уровня файла (`line: null`) — первыми в узле файла, с пометкой «весь файл».
- **Переход к коду:** двойной клик / Enter — открыть файл на строке (`OpenFileDescriptor`); автопрокрутка к коду при выборе (переключатель).
- **Действия над ошибкой** (контекстное меню и панель инструментов):
  - «Игнорировать через @phpstan-ignore» — та же чистая функция, что в quick-fix 01a;
  - «Копировать сообщение», «Копировать идентификатор»;
  - «Открыть документацию по идентификатору».
- **Фильтр** по тексту сообщения и идентификатору; переключатель группировки «по файлам» / «по идентификаторам».
- **Перезапустить** последний запуск с теми же файлами.
- **Устаревшие результаты:** если файл изменён после прогона, узел файла помечается «изменён после проверки» (номера строк могут съехать).
- **Экспорт** отчёта в Markdown (в буфер обмена или файл) — чтобы приложить к ревью.
- Пустой результат — «Ошибок не найдено» с итогами в шапке.

Отчёт показывает результаты запусков из панели и меню; результаты подсветки в редакторе в него не смешиваются.

## Связь с редактором

- В полосе над редактором (ошибки уровня файла, 01a) добавить кнопку **«Открыть отчёт»**.
- Действие «Показать в отчёте» из контекстного меню редактора — опционально.

## Иконка

Проверено (2026-10): код PHPStan распространяется под **MIT** (Copyright Ondřej Mirtes, PHPStan s.r.o.). Файлы логотипа (`website/src/images/logo.png`, `logo-big.png`, `favicon.png`) лежат в том же репозитории; отдельной лицензии или правил использования бренда у логотипа нет. Зарегистрированного товарного знака «PHPStan» найти не удалось — это не юридическое заключение.

Решение:

- Для иконки **панели** использовать официальный логотип PHPStan, упрощённый до 13×13 SVG (светлая и тёмная версии); в README и `<description>` указать, что логотип принадлежит проекту PHPStan и используется под MIT, плюс ссылка на репозиторий. Не выдавать плагин за официальный.
- Перед публикацией в маркетплейс написать автору (GitHub Discussions phpstan/phpstan) и спросить разрешения. Если ответ отрицательный или логотип плохо читается в 13×13 — запасной вариант: своя иконка — щит с галочкой или монограмма «PS».
- Иконка самого **плагина** в маркетплейсе (`pluginIcon.svg`) — своя, без логотипа PHPStan, чтобы не выглядеть официальным плагином.

## Тесты

- Модель отчёта (чистая логика): группировка по файлам и по идентификаторам, сортировка, фильтр, подсчёт итогов, экспорт в Markdown.
- Сборка команды для нескольких файлов и разбиение на пачки по длине командной строки.
- Отбор изменённых файлов (PHP, без vendor/excluded) — на чистой функции над списком путей.

## Ручная проверка (в `playground/`)

1. Изменить 3 PHP-файла: они видны во вкладке «Изменённые файлы»; «Проверить все изменённые» — один процесс PHPStan, отчёт по трём файлам.
2. Снять галочку с одного файла — «Проверить выбранные» проверяет два.
3. Двойной клик по ошибке — переход на строку; ссылка на идентификатор открывает phpstan.org.
4. «Игнорировать» из отчёта — комментарий `@phpstan-ignore` в коде.
5. Фильтр и группировка по идентификатору работают; экспорт в Markdown читается.
6. Изменить файл после прогона — пометка «изменён после проверки».
7. Режим `MANUAL` из 01a: в редакторе подсветки нет, панель работает.
8. Контекстное меню Project → «Проверить PHPStan» на папке `app/Models`.
9. «Проверить проект» — подтверждение, затем полный прогон с прогрессом; отмена убивает процесс.
10. Docker-режим: всё то же самое через контейнер, пути в отчёте — локальные.
11. Сломанный `phpstan.neon` — блок ошибки в отчёте и одно уведомление.

## Не делать

- Не запускать проверку панели автоматически при открытии проекта или при изменении VCS — только по действию пользователя.
- Не хранить отчёт между сессиями IDE (в v0.1).
- Не делать сетевых запросов.
