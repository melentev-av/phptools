# Psalm Integration for OpenIDE

Проблемы [Psalm](https://psalm.dev) прямо в редакторе OpenIDE — с точными колонками, info-проблемами и панелью с отчётом.

> Плагин для OpenIDE. Работа в IDE JetBrains не поддерживается и не тестируется.

## Требования

- Psalm в проекте (`composer require --dev vimeo/psalm`) либо путь к бинарнику в настройках.
- Конфигурация `psalm.xml` (создать: `vendor/bin/psalm --init`).

## Как работает

- Проверяется открытый файл, в рабочей папке ближайшего владельца `vendor/` — там же Psalm находит `psalm.xml`.
- **Только сохранённые файлы:** у Psalm CLI нет режима анализа несохранённого буфера. Режим «При вводе» ведёт себя как «При сохранении»: подсветка обновляется после Ctrl+S.
- Подсвечивается точный фрагмент (колонки Psalm считаются в байтах — плагин пересчитывает их в символы, поэтому кириллица в строке ничего не сдвигает).
- Info-проблемы (с `--show-info`) — слабые предупреждения.
- Подсказка: сообщение и тип проблемы ссылкой на документацию psalm.dev.
- Quick-fix (Alt+Enter) «Подавить через @psalm-suppress» вставляет `/** @psalm-suppress <Type> */` над строкой или дописывает тип через запятую в такой же однострочный комментарий. Многострочные докблоки не трогаются.
- Файлы вне `projectFiles` пропускаются молча.
- Включается и выключается инспекцией **Psalm validation** (Settings → Editor → Inspections → PHP tools); Code → Inspect Code тоже запускает Psalm.

## Панель Psalm

Иконка Psalm в левой полосе: вкладки **Изменённые файлы** (PHP-файлы из VCS, проверка выбранных, всех, текущего файла или всего проекта) и **Отчёт** (дерево «файл → проблемы», ссылки на psalm.dev, переход к коду, подавление проблемы, фильтр, группировка по типу, экспорт в Markdown). В дереве Project — «Проверить Psalm» для файлов и папок.

## Настройки

Settings → Tools → Psalm. Хранятся в `.idea/psalm-tools.xml` — файл можно коммитить.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| Когда проверять | При вводе | «При вводе» = «При сохранении» для Psalm; «Только вручную» — Inspect Code и панель |
| Бинарник | пусто | Пусто — `vendor/bin/psalm` рядом с файлом и выше до корня проекта |
| Файл конфигурации | пусто | `-c`; пусто — Psalm ищет `psalm.xml` сам |
| PHP-интерпретатор | пусто | Запуск как `<php> <psalm>` |
| Доп. аргументы | пусто | Добавляются в командную строку |
| Таймаут | 60 с | Один запуск |
| Показывать info-проблемы | выкл. | `--show-info=true` |
| Потоков | 1 | `--threads`; больше 1 — быстрее на всём проекте, но тяжелее при каждом сохранении |

Кнопка **«Проверить»** запускает `psalm --version` с текущими настройками.

## Docker Compose / Laravel Sail

Включите «Запускать в Docker Compose» и укажите сервис (для Sail — `laravel.test`, путь `/var/www/html`). Плагин выполняет `docker compose exec -T -w <папка> <сервис> vendor/bin/psalm …` из корня проекта; пути из контейнера в отчёте показываются локальными.

## Встроенный Psalm PHP-плагина

Если у PHP-плагина OpenIDE включена своя проверка Psalm, при открытии проекта плагин предложит её выключить, чтобы проблемы не подсвечивались дважды.
