# PHP-CS-Fixer Integration for OpenIDE

[PHP-CS-Fixer](https://cs.symfony.com) прямо в редакторе OpenIDE: подсветка мест, которые он поменял бы, исправление прямо из diff, исправление файлов и папок, панель с отчётом.

> Плагин для OpenIDE. Работа в IDE JetBrains не поддерживается и не тестируется.

## Требования

- PHP-CS-Fixer в проекте (`composer require --dev friendsofphp/php-cs-fixer`) либо путь к бинарнику в настройках.
- Конфигурация `.php-cs-fixer.php` или `.php-cs-fixer.dist.php` в корне (рядом с `vendor/`).

## Как работает

- **Подсветка.** Код из редактора передаётся PHP-CS-Fixer через stdin в режиме `--dry-run --diff`, поэтому проверяются и несохранённые изменения, а diff всегда соответствует тексту в редакторе. Места, которые поменяются, подсвечиваются слабым предупреждением; в подсказке — названия фиксеров и diff.
- **Quick-fix (Alt+Enter)** — без повторного запуска PHP-CS-Fixer, прямо из diff:
  - «Применить исправление PHP-CS-Fixer» — только это место;
  - «Исправить весь файл через PHP-CS-Fixer» — все места одной правкой.
  Оба работают через обычное редактирование документа (Ctrl+Z откатывает) и недоступны, если документ изменился после проверки.
- **«Исправить через PHP-CS-Fixer»** (меню Code, контекстное меню редактора и дерева Project) — настоящий `php-cs-fixer fix` для текущего файла, выделенных файлов и папок. Несохранённые документы сначала сохраняются, после исправления IDE перечитывает файлы; приходит уведомление «исправлено файлов: N».
- Файлы, исключённые в `Finder` конфигурации, не подсвечиваются (плагин сверяется с `php-cs-fixer list-files`, кэш 30 с).
- Файлы с синтаксической ошибкой пропускаются молча — синтаксис подсвечивает PHP-плагин.
- Включается и выключается инспекцией **PHP-CS-Fixer validation** (Settings → Editor → Inspections → PHP tools).

## Панель PHP-CS-Fixer

Иконка в левой полосе: вкладки **Изменённые файлы** (PHP-файлы из VCS; проверить выбранные, все, текущий файл или весь проект) и **Отчёт** — какие строки поменяются («что было → что станет» и фиксеры). В отчёте: переход к коду, «Исправить файл через PHP-CS-Fixer» для выбранных файлов и для всех файлов отчёта, экспорт в Markdown. В дереве Project — «Проверить PHP-CS-Fixer».

## Настройки

Settings → Tools → PHP-CS-Fixer. Хранятся в `.idea/php-cs-fixer-tools.xml` — файл можно коммитить.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| Когда проверять | При вводе | «При вводе», «При сохранении» или «Только вручную» (Inspect Code и панель) |
| Бинарник | пусто | Пусто — `vendor/bin/php-cs-fixer` рядом с файлом и выше до корня проекта |
| Файл конфигурации | пусто | `--config`; пусто — PHP-CS-Fixer ищет сам |
| PHP-интерпретатор | пусто | Запуск как `<php> <php-cs-fixer>` |
| Доп. аргументы | пусто | Добавляются в командную строку |
| Таймаут | 20 с | Один запуск (исправление и панель — дольше) |
| Рискованные правила | выкл. | `--allow-risky=yes` |

## Docker Compose / Laravel Sail

Включите «Запускать в Docker Compose» и укажите сервис (для Sail — `laravel.test`, путь `/var/www/html`). Код передаётся в контейнер через stdin (`docker compose exec -T …`), на хосте временные файлы не создаются.

## Встроенный CS-Fixer PHP-плагина

Если у PHP-плагина OpenIDE включена своя проверка PHP CS Fixer, при открытии проекта плагин предложит её выключить. Встроенный в PHP-плагин Reformat Code через CS-Fixer — отдельная настройка PHP-плагина, этот плагин её не трогает.

Fix on save в v0.1 нет.
